# 운영과 문제 해결

## 일상 운영

현재 기본 모드는 수동 요청 전용입니다. 프로젝트 채팅의 명시적인 요청이 있을 때만 작성·검토·발행합니다. 같은 날 추가 요청도 새 주제로 처리하며, 컴퓨터와 앱을 켜 두어도 정기 발행은 하지 않습니다.

`app_runner.py prepare`는 manual_request 정책이면 저장소 상태·잠금·WordPress를 조회하기 전에 skip으로 끝납니다. 기존 앱 자동화는 중지 상태를 유지합니다. 일정을 다시 활성화하려면 별도의 사용자 요청이 필요합니다.

## 상태와 복구

원고 id와 내용 해시로 기존 글을 대조하고 fcntl 잠금으로 동시 로컬 실행을 막습니다. API 쓰기 응답이 불명확한 경우 새 글을 바로 만들지 않습니다. 상태에는 pending, verify-pending, draft, publish-pending, publish, future 등의 단계가 저장됩니다.

```bash
.venv/bin/python blog.py status
.venv/bin/python blog.py doctor
```

`state/`를 삭제하면 중복 방지와 복구 근거를 잃습니다. 원고나 서버 글을 임의로 수정했으면 자동 복구가 중단될 수 있습니다. 기록된 글 ID와 실제 서버 글을 대조한 뒤 작업을 진행하세요. 같은 원고를 재발행하려고 id를 바꾸는 행동은 복구 방법이 아닙니다.

API 타임아웃과 상태 불일치가 있으면 이 프로젝트를 연 Codex에 다음처럼 요청할 수 있습니다.

> 최근 발행 오류를 조사하고 state 기록과 실제 WordPress 글을 대조해줘. 새 ID나 새 글을 만들지 말고 기존 쓰기 결과를 먼저 확인하고 복구해줘. 인증 값은 출력하지 말아줘.

## 흔한 오류

| 증상 | 확인할 내용 |
|---|---|
| auth 요구·401·403·토큰 만료 | blog.py auth로 재인증, 대상 사이트 권한 확인 |
| 토큰 파일 권한 오류 | 파일 600, 비밀 폴더 700 확인 |
| 8080 포트 충돌 | OAuth callback에 사용하는 포트를 점유한 프로그램 확인 |
| 해시 불일치 | 원고 변경 후 원문을 다시 검토하고 새 해시 저장 |
| 근거 인용을 찾지 못함 | 실제 수집 text에 quote가 그대로 있는지 확인 |
| 출처 날짜 오류 | 발표일과 수집일, news/background, 미래 날짜 확인 |
| 허용되지 않은 호스트 | 공식 사이트 신원을 확인하고 정확한 호스트만 등록 |
| 후보 수 부족 | 선정 기록에 서로 다른 후보 URL 10개 이상 조사 |
| HTML·이미지 권리 오류 | CONTENT.md의 허용 형식 및 실제 이미지 파일 확인 |
| 이미 발행됨 | 자동 경로는 정상 종료, 추가 글은 수동 경로 사용 |
| WordPress 초안이 변경됨 | 관리자에서 수정한 내용과 로컬 기록을 대조 |

## 인증 정보

.env와 .secrets/는 실제로 평문 파일입니다. 파일 권한 제한은 암호화를 뜻하지 않습니다. 외부 저장소·ZIP·공유 채팅에 넣지 마세요. 공개 배포본에는 빈 .env.example만 포함합니다. state와 원문 패킷도 운영용이므로 기본 공개 대상에서 제외합니다.

백업이 필요하면 운영 원고·이미지·state·인증을 비공개 저장소나 적절한 보호 방식으로 별도 관리하세요. 토큰을 노출했다면 삭제만으로 해결했다고 가정하지 말고 WordPress 측에서 폐기·재발급해야 합니다.

## 테스트와 현재 검증 범위

```bash
.venv/bin/python -m unittest discover -s tests
```

71개 테스트는 모의 API로 중복 저장, 불명확한 쓰기 복구, 해시 변경, 승인 전 발행 차단, 날짜 정책, HTML·권리 정보, 이미지 재사용, 대표 이미지, 행 색상 등을 검사합니다. 테스트는 실서비스 발행을 하지 않습니다.

실제 운영 환경에서 초안·공개·대표 이미지와 같은 날 중복 방지는 확인했습니다. 모든 테마, 계정, 새 컴퓨터, 미래 예약 실행의 성공을 보증하지 않습니다. Python 구조 검사가 내용의 사실성이나 이미지의 실제 권리를 보증하지 않습니다.

## 제한 사항

- WordPress.com REST v1.1과 OAuth를 사용하며 자체 설치 WordPress의 application password 경로를 구현하지 않았습니다.
- 사이트 주소와 자동 원고 카테고리는 일부 코드에 고정되어 있습니다.
- 최신 광범위한 주제 조사는 Codex가 수행하며 Python RSS 수집은 일부 공식 채널에 한정됩니다.
- 별도 AI API, GitHub Actions AI 작성, 컴퓨터 자동 깨우기 설정은 포함하지 않습니다.
- 수동 preview 스타일은 공개 렌더러와 완전히 같지 않습니다.
- 이미 공개된 글을 변경하는 일반 update CLI는 제공하지 않습니다. 수정 요청은 실제 글과 로컬 기록을 대조하는 별도 작업입니다.
